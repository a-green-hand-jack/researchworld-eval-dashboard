# Analysis artifact map for presentation and report owners

All paths here are relative to the eventual `analysis/` directory in paper-repo.
`src/analyze_results.py` consumes only completed main/perturbation runs and writes:

| Result file | Checkable use |
|---|---|
| `results/summary/main_descriptive.csv` | Per-frame/cap/rule/group costs, feasibility, zero-cost count; raw and n-normalized medians. Use paired mean-rank groups to compare rules. |
| `results/summary/paired_vs_mean.csv` | Same-target comparisons vs mean: finite-pair differences/ratios plus both/only-one feasible counts. Different denominators are explicit. |
| `results/summary/perturbation_intervals.csv` | Fixed target ranks2–11: task-mixture and assumed-noise 2.5/97.5 percentiles and feasibility. These are sensitivity intervals. |
| `results/summary/paired_perturbation_targets.csv` | Same-draw rule-vs-mean changes for each fixed target; difference percentiles condition on both feasible, counts show all feasibility classes. Generated by `src/summarize_perturbations.py`. |
| `results/summary/paired_perturbation_panel.csv` | Across-draw sensitivity of fractions of the fixed ten-target panel with lower/higher costs; both-infeasible remains separate. Generated by `src/summarize_perturbations.py`. |
| `results/summary/taskcount_intervals.csv` | HELM task-count sensitivity, selected positions2/5, raw and normalized medians. No cross-dataset causal scaling claim. |
| `results/summary/targeting_controls.csv` | Random-order K vs optimal K; capped uniform L1 vs optimal L1 on ranks2–21. |
| `results/data_audit.json` | Frame sizes, score bounds, leaders, processed-input hashes. |
| `results/pilot.csv` and `logs/suite_*.json` | Observed runtimes and exact commands. |

Raw optimizer output files (one row per target/cap/rule) are authoritative for
individual examples. No figure should hide infeasibility by dropping infinities
without displaying the feasible fraction. Do not pool full OLLB and top500
frames or compare raw K/L1 between six and57 tasks as if units were identical.
The primary measures are independently optimized; the L1 optimum is not
necessarily the same intervention as the K optimum.

The final report/figure filenames are chosen by their owners. They should add
their actual plot/table script→artifact mapping in the delivery root. This map
identifies source result tables, without taking over final presentation.

`docs/REVIEW_RESPONSE.md` records the scope and outstanding checks. A diagnostic
or pilot marked incomplete is not final evidence.

`src/check_trimmed_zero_gap.py` writes
`results/solver_checks/ollb_extra_rules_zero_gap.csv` and
`results/trimmed_zero_gap_validation.json`: fresh500-row supplementary-panel
validation of the explicit zero relative MIP-gap request (100 trimmed rows),
plus score-rule tests, runtime and source hashes. The fresh CSV is byte-identical
to the authoritative `results/ollb_extra_rules.csv`; no figure input changes.

`docs/FINAL_EXTENSION_FINDINGS.md` records checked results and their limits;
`results/final_*_validation.json` and `clean_final_*.json` are the distinct
completeness/reference and fresh-regeneration gates. A pilot or an absent gate
is not evidence that a group is ready.

Final addition summary points and denominators can be independently checked with
`src/check_final_results.py --stage controls-summary`, `--stage frames-summary`
and `--stage scales-summary` after their respective summaries exist. The raw
frame check independently reconstructs seed31 selected matrices and diagnostics;
the scale check reconstructs per-task SD/IQR and cap monotonicity.

Completed original-study clean gate: `src/clean_reproduce.py` generates
`clean_reproduction.json`/`clean_reproduction_runtime.json` after all16 original
cost/panel CSVs complete. `src/audit_clean_completion.py` produces the separate
`clean_reproduction_artifacts.json` with keyed numerical rechecks, CSV/metadata
hashes, invariant-check scope and measured stage-time sums. Successful stage
logs are in `logs/clean_completed/`; the failed120s proof attempt remains under
`logs/clean_failure_120s/`. Later extension clean checks are separate records.
