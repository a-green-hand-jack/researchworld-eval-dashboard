# paper-repo: "Which Benchmarks to Run?" — paper, code and reproduction notes

Question: given a historical model x benchmark score matrix with missing cells and a new model that can run only k benchmarks, which k to run, how to infer the other scores, and how large must k be.

## Seeds, protocol, runs
`--seed 0` everywhere; repetition i uses `default_rng(1000*seed+i)`, factor-analysis initialisation seed i. Repetitions of 10-fold CV: 3 on MTEB-56, 2 on MTEB-275/357/sparse, 5 on HELM-MMLU; random selector 10 draws per fold (5 on the Open LLM Leaderboard). Bootstrap: 500 resamples over held-out models, paired for differences. Protocol, selectors, inference rules, metrics, pre-fixed k criterion and the list of runs are in `results/README.md` and Section 4 of the paper.

## Commands (from the repository root)
```
bash code/fetch_data.sh
python code/extract_mteb.py <mteb results dir> <processed dir>
python code/build_matrices.py <data dir> data
python code/synthetic.py data/matrices
bash code/launch_primary.sh [group]    # the primary protocol-B runs (B_*; includes B_helm_mmlu and B_helm_lite_ext)
bash code/launch_sweeps.sh [group]     # each line is one plain `python code/run_cv.py ...` call (written for `ht-resource run`; the command lines can be run directly)
bash code/launch_review.sh [group]     # second-round analyses: extra selectors/rules (xrun), cluster bootstraps, detector, diagnostics, extra baselines
python code/build_helm_ext.py ...      # HELM-Lite-28 matrix (91 x 28) from the pinned HELM Lite export
python code/analyze.py <run> ...       # raw -> results/summary
python code/oracle_table.py <dataset>; python code/leak_table.py <leak_run> <B_run> <name>; python code/kstar_table.py
python code/describe_data.py; python code/summarize_conditions.py; python code/noise_floor.py
python code/theory_check.py results/theory; python code/theory_vs_real.py <dataset> ...
bash code/figtab/make_all.sh           # every figure and table from results/summary and results/theory
bash code/check.sh                      # 12 s end-to-end reproduction check (helm_mmlu, tiny run) against results/check/expected.csv
bash paper/build.sh                    # paper/paper.pdf
```
`LOCAL=1 bash code/launch_*.sh` runs every line sequentially as plain python instead of through `ht-resource run`.
Raw per-model result tables (`results/raw/*.parquet`, hundreds of MB) are not in git; they are regenerated by `code/launch_*.sh` or downloaded as the release `raw-results-1` of world/experiment-repo (see `results/README.md`, "Raw results"). The summaries under `results/summary` and `results/theory` are what figures, tables and the paper read.

## Unfinished and failed work
* No primary run is unfinished: `B_mteb_sparse` (2 repetitions) and `F_mteb_sparse` finished and are reported (Sec. 5.5, Appendix B). The sparse matrix appears in Tables 1, 2, 5, 9 and 10 and in Fig. 4b and Fig. A3 (figtab-repo, merged); the sparse numbers in the text come from `results/summary` (`curves_B_mteb_sparse.csv`, `paired_B_mteb_sparse.csv`, `kstar_table.csv`, `cluster_kstar_B_mteb_sparse.csv`, `sparse_population.csv`, `results/theory/vs_real_trainonly_mteb_sparse.csv`).
* The sparse matrix has two repetitions and models with fewer than k scores are skipped for that k, so large-k points rest on fewer models.
* The temporal split on MTEB-56 fails to extrapolate (even the full-information floor is about 1.4 nMSE); M = 15 is unstable for k > M; cost-aware selection is unstable on MTEB-275. These are reported in the paper as results, not hidden.
* The Bayes curve is optimistic on real matrices even with a train-only covariance (20-30% below the cross-validated error on MTEB); the paper states that.
* The cluster-bootstrap k* for conditional variance with the factor posterior at g=0.9 (20) differs from Table 1 (16) because the lower bound grazes 0.9; the paper notes it.
