# Reproduction notes — regression-based GATE estimation under network interference

All numbers/figures/tables of the paper derive from the code in this repository (`code/`, `code/scripts/`) and the tables in `results/`.
(Layout: library `code/netgate/`, drivers `code/scripts/`, tests `code/tests/`, analytic notes `code/docs/THEORY.md`.)

## Environment
Python 3.11; numpy, scipy, pandas, pyarrow, scikit-learn, networkx 3.6.1 (versions printed by `python3 code/scripts/versions.py`, recorded in
`results/MANIFEST.md`). CPU only. No GPU, no network needed after the two graph files are downloaded.

## Seeds
Base seed 20261102. Each (cell, graph draw) gets `SeedSequence([base_seed, hash(cell spec), graph_index])`, split into independent streams for
graph, baselines, assignments/noise and graph perturbation (`netgate.sim.setup_graph`). A cell's id is the SHA-1 of its JSON spec, so changing any
parameter changes the seeds. Estimators within a replicate share the same (z, y) (paired comparisons).

Exact regeneration: a cell's random streams come from the SHA-1 of its exact spec, so `experiments.py` reproduces the delivered numbers only if it emits
the very specs stored in `results/config.json`. It does for every experiment (checked: all 14 delivered experiments, 0 cell-id differences). E0_valid and MAIN were run when
the base graph spec carried an inert `k` (ignored for non-SBM graphs); `_main(legacy_k=True)` and the `k=30` in E0_valid keep it so the ids still agree.
MAIN_s2 uses base seed 777 (`SEEDS` in `experiments.py`, applied automatically; `--seed` overrides). Check one cell against the delivered table:
`python3 code/scripts/check_cell.py MAIN 'er|M1|bern0.5'` re-runs it and compares every observed-fit `tau_hat` with `results/replicates.parquet`
(prints `IDENTICAL`; verified for MAIN, MAIN_s2, E0_valid, E1_size). `run_experiments.py --from-config results/config.json` replays any stored spec list directly.
Revision that produced `results/`: the MAIN/E1-E11 tables were generated by revisions up to `fe30525` (`results/MANIFEST.md` records the export revision); `experiments.py`
has changed since only by the legacy-key option, the `MAIN_s2` / `MAIN_realdraws` definitions and `SEEDS` (no change to any delivered cell spec).

Derived files: `export.py` (merges `results/raw/*.parquet` into `results/replicates.parquet`, `summary.csv`, `diagnostics.csv`, `config.json`, `MANIFEST.md`);
`contrasts.py <ids>` (paired MSE ratios -> `contrasts.csv`; pass **all** ids, it overwrites the file:
`MAIN MAIN_s2 MAIN_realdraws E1_size E2_degree E3_gamma E4_curv E5_graphs E6_spec E7_model E8_design E9_noise E10_coverage E11_grapherr [MAINML]`);
`analysis_h7.py` (-> `h7.csv`; excludes MAIN_realdraws); `realdraws.py` (MAIN_realdraws -> `realdraws_perdraw.csv`, `realdraws_summary.csv`: rel. RMSE per baseline draw, mean/SD/min/max across draws, and in how many draws OLS(z,f) beats DM); `theory_check.py <ids>` (-> `theory_check_{var,bias}.csv`).

## Compute and measured run times
Hardware: jobs and sandbox were containers limited to 2 CPUs and 4 GB RAM on a shared host (Intel Xeon Gold 6230 @ 2.1 GHz, 40 logical CPUs, 257 GB, no GPU)
whose load was ~30 during the runs, so wall times below are upper bounds for an idle 2-CPU machine. `--procs 2` (one cell per process).
Wall time is the elapsed time of the job that ran the group (from `ht-resource`), not CPU time; groups sharing a job are reported together.

| group | wall time (2 procs) | notes |
|---|---|---|
| E0_valid + MAIN (76 cells) | 1.3 ks (21 min) | one job |
| MAIN_s2 (48 cells) | 1.1 ks | |
| E1, E2, E3 (not E4/E7), E5, E6, E8, E9, E10, together | 5.7 ks (95 min) | one job; E8 0.50 ks and E5 1.2 ks of it |
| E4_curv (90 cells) | 3.2 ks | |
| E11_grapherr (24 cells, 8-12 graph draws) | ~0.15 ks | |
| E7_model (6 cells) | 75 ks (21 h) | run **without** thread limits: the gradient-boosting/ridge fits oversubscribed the host's threads (see below) |
| theory_check (all) | 2.3 ks | |
| export.py / contrasts.py (all ids) / analysis_h7.py | 32 s / ~60 s / seconds | export peak RSS 3.5 GB |
| tests | < 1 min | |

Thread oversubscription: scikit-learn's `HistGradientBoostingRegressor` and the BLAS calls use all host threads by default; in a 2-CPU container on a loaded
40-core host this made ridge/GBM cells ~100x slower (E7: 15-43 ks per cell; a first MAINML run was stopped after 138 ks with only the ER cells printed).
With `OMP_NUM_THREADS=OPENBLAS_NUM_THREADS=MKL_NUM_THREADS=1` a pilot ridge+GBM+OLS(z,f) cell on ER needs ~0.4 s per replicate. Always set these when running MAINML/E7.
Memory: a Stanford3 cell (n = 11,586; 568k edges) peaks at ~1.5 GB per process (so `--procs 2` fits in 4 GB); synthetic cells are well below. Not measured per group otherwise.

## Files in `results/`
`replicates.parquet` long table (one row per replicate × estimator; `fit_data` = observed or population (noise- and baseline-free fit used for the
approximation error); schema in `results/SCHEMA.md`), `summary.csv` (bias, SD, RMSE, relative RMSE, MC standard errors, coverage), `diagnostics.csv`
(per cell/estimator: population-level approximation error, exposure-support statistics), `config.json` (all cell specs), `MANIFEST.md`
(code revision, inputs, reps per cell), `theory_check_*.csv` (analytic predictions vs simulation).
