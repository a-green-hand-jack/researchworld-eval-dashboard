# Repeat-run reliability of sampling-based SHAP attributions on tabular models

Code, results and paper for "When Is One Run Enough? Repeat-Run Reliability of Sampling-Based SHAP Attributions on Tabular Models".

* Paper (ICML 2026 template, 8-page main-text limit, main text ends on p. 6): `paper/main.pdf`, LaTeX source `paper/main.tex`, bibliography `paper/refs.bib`, generated table fragments `paper/tables/*.tex`.
* Code: `code/`. Results (all raw outputs, tables, figures): `results/`. One-shot pipeline: `run_all.sh`.
* Every number in the paper's tables/figures is produced by the scripts below. Numbers quoted in the running text were transcribed by hand from `results/tables/*.csv` and `results/headline_numbers.json` (generated by `code/make_paper_tables.py`); please check text against those files.

## Seeds

* Train/test split: `random_state=0`. Models: `random_state=0` (main), bootstrap-retrained models: bootstrap `RandomState(500+k)`, model seed `k+1`, k=0..4.
* Background (100 train rows) and the explained instances (100; 50 for German): `RandomState(1000 + dataset_index)` (`run_core.setup`).
* Estimator runs: `np.random.default_rng([20261111, dataset, model, instance_position, scale, estimator, budget_mult])`.
* Background resampling (yardstick): `RandomState(9000 + 17*draw + B)`. Default-shap experiment: `np.random.seed(100000*(instance+1)+run)` before every explainer call (permutation explainer also gets `seed=`).
* Bootstrap / test code in `analysis_*.py` use fixed `default_rng` seeds (11, 21, 5, 3, 7, 31, 99).

## Method summary (see paper)

Value function: interventional (marginal) expectation over a 100-row random training background; players are original attributes. Budget m = number of distinct coalition evaluations (each = 100 model calls), grid m/d in {2,4,8,16,32,64} (<=32 for German). For d<=12 all 2^d coalition values are tabulated per instance (exact Shapley values, all runs read from the table); for German (d=20) the model is called live and the reference is the mean of 20 permutation runs at 64d (approximate). KernelSHAP is a re-implementation of shap's coalition allocation + weighted least squares (`code/shapsim.py`), validated against the package; permutation sampling is antithetic. 50 runs per (instance, estimator, budget) (30 for German).

## Deviations, caveats and things not done (honest list)

* The main experiment uses our own re-implementation of the estimators (needed to control budgets and to make millions of runs affordable). Validation against shap was done on Pima (d=8) only. shap's default l1 feature selection (relevant for larger d at low coverage) is not reproduced in the main experiment; the default-shap experiment (E5) uses the package itself.
* For m = 2d, Kernel SHAP's normal equations are ill-conditioned in 14-23% of random designs (both in our code and in shap); these cells are reported but not interpreted.
* One trained model per (dataset, model) in the main experiment; 100 instances (50 for German); a single ACS state (CO, 2018); d between 8 and 20. No deep tabular architectures (ResNet/FT-Transformer) and no conditional-expectation SHAP.
* German reference attributions are estimated, not exact; accuracy-to-reference there is approximate.
* Log-odds sensitivity analysis clips probabilities to [1e-6, 1-1e-6]; this distorts RF (probabilities of exactly 0/1).
* `results/validate_impl.csv` (08:06) was produced by a run of `validate_impl.py` that started before the late change to the LR/MLP feature encoder (winsorisation) and the MLP `early_stopping` change in `models.py`; the main/yardstick/default-shap experiments ran after that change. The validation compares estimators on whatever model is given (tree models and MLP; no LR), so it does not depend on the encoder, but its MLP is the earlier configuration. A re-run was started and aborted for time; it truncated `results/validate_impl.log`, so the printed summary was regenerated from the CSV as `results/validate_impl_summary.txt`. Re-running `validate_impl.py` reproduces the experiment with the current `models.py` (expect nearly identical estimator-vs-shap ratios).
* The "margin-to-noise" AUCs (Fig. 2) use noise measured from the same runs; they are a consistency check, not out-of-sample prediction. The in-run z certificate is the out-of-sample (single-run) predictor.
* Per-cell tests and the cell-level Spearman correlations are exploratory; only the Kernel-vs-permutation and the yardstick-vs-sampling tests are Holm-corrected.
