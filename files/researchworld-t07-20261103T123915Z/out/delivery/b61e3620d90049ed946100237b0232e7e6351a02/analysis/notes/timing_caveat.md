The original record, parameters and convergence attempts are retained without alteration. Do not report the sum of this field as active runtime, or silently subtract an estimated pause.

A supplemental timing-only replication is implemented in `diagnostics/measure_suspended_fit.py`. It uses the identical frozen fitting rows, dimension, algorithm and seed, checks the objective against the preserved original, records both process CPU seconds and elapsed seconds, and never replaces fitted parameters or hyperparameters. Its result will be `results/study/timing_replication.json`. This additional measurement does not modify any estimator or statistical configuration and uses no target responses. Source fitting outside the affected record retains measured elapsed rather than process CPU time; shared-host contention and pauses can affect elapsed time. The original resource job accounting is an additional whole-job CPU observation, not per-fit timing.

For subsequent commands `diagnostics/run_measured.py --record <json> -- <command>` records child user/system CPU seconds, elapsed wall seconds, process peak RSS, exit status and thread environment. This wrapper changes no predictions. These whole-command records measure actually executed cost, including cache/loading/output overhead. Within `.timings.parquet`, anchor-ridge's selection cost includes the same anchor construction used by anchor-mean: those are method-alone costs, not independent physical executions to sum. Mixture variants mark shared p-IRT inference with zero separately assigned inference seconds; this denotes reuse, not a claim that mixing arithmetic is free. Whole-command CPU is the correct executed aggregate; standalone per-method costs answer a different amortization question. MIRT fit costs are counted once per saved cache entry and can serve several budgets or methods.
