# Choosing k benchmarks and inferring the rest — code and reproduction guide

Paper: `paper/main.pdf` (LaTeX source `paper/main.tex` + `sec_*.tex`, `app_*.tex`, `refs.bib`, NeurIPS 2026 style `neurips_2026.sty`;
build with `cd paper && latexmk -pdf main.tex`).  Everything below is CPU-only.

## Layout
```
code/                 all code (bsel/ = library)
  bsel/fa.py          factor analysis with missing data (EM) + fold-in
  bsel/predict.py     predictors (Mean, AvgShift, Gauss, FA, ISVD, kNN, Hybrid) + inner-split tuning
  bsel/select.py      selection rules (greedy variance-reduction, max-var, MI, k-medoids, central, top-SNR, exhaustive)
  bsel/protocol.py    hold-out-model protocol with fixed held-out targets T0
  extract_mteb.py     MTEB results repo -> model x task matrix
  mteb_task_meta.py   task types/languages from the `mteb` package (metadata only)
  prep_data.py        builds all processed matrices in /work/data/proc
  run_real.py         real-data experiments (random / new-organisation / temporal splits)
  run_conditions.py   data-condition ablations on MTEB-main
  run_bias.py         protocol-pitfall experiment (complement vs fixed targets)
  run_synth.py        synthetic checks of the theory (E1-E6)
  analyze_lib.py, make_results.py   bootstrap CIs, all tables and figures
  tests.py            sanity tests of the closed forms (python code/tests.py)
  requirements.txt    pinned versions
  get_data.sh, run_all_real.sh, run_everything.sh   drivers
paper/                paper sources, figs/ (PDF), tables/ (LaTeX fragments + CSV)
out/                  raw results (parquet), synthetic CSVs, logs, summary.json
```

## Environment
Python 3.11.2 in a venv; `numpy 2.4.6, scipy 1.17.1, pandas 3.1.0, matplotlib 3.11.2, pyarrow 26.0.0` (scikit-learn 1.9.1 is installed but not used).
Task metadata for MTEB was dumped once with `mteb==2.26.31` in a *separate* venv (`pip install mteb==2.26.31; python code/mteb_task_meta.py <out.csv>`); the resulting
`mteb_task_meta.csv` is the only artefact used (it is regenerated by `get_data.sh` only if you uncomment the line). `pypdf`/`pymupdf` were used only to inspect the compiled PDF.
Single-threaded BLAS is used (`OMP_NUM_THREADS=1`) and a process pool across folds.

## Run
```
bash code/get_data.sh          # ~5 min + download
bash code/run_everything.sh    # synthetic + real experiments + tables/figures; ~1 h wall-clock on 40 cores (see Timings)
cd paper && latexmk -pdf main.tex
```
Seeds: fold assignment uses `default_rng(100+repeat)`; per-fold seeds are `crc32(fold name) % 10000` (tuning, random selection, k-medoids); synthetic experiments use fixed seeds inside `run_synth.py`; bootstrap seed 0 (2000 replicates). Results are deterministic.

## Negative results, discarded variants and honest notes
* A first version of the protocol scored each selector on the complement `C \ S` of its own selection; it favoured greedy selection spuriously (Section 4.6 of the paper). All reported results use fixed held-out targets; the old runs were deleted and not used.
* The Hybrid (pairwise + factor model) predictor and the rank-r factor model did not beat the shrunk full pairwise covariance for k <= 10; the factor-model covariance is a worse *selection* covariance than the pairwise one (App. table "oracle"). kNN beats the Gaussian predictor at k=1.
* The default predictor (Gauss) was chosen after seeing inner-validation scores on MTEB-main (training rows only).
* Greedy selection is *worse* than random on LiveBench-7 at k=3 and not better than random for k >= 40 on MTEB-main.
* kNN had a bug at k=1 in the very first exploratory run (no neighbour qualified); fixed before the reported runs.
* LiveBench dump has only 7 tasks per model; its time split is not used. HELM Lite fine-grained columns are sub-scenario scores of MMLU/LegalBench/WMT plus the other scenarios.

## Restricted material
The task forbids reading a specific published paper on this question. I did not search for it by title/author/results. My literature checks were limited to verifying the existence and bibliographic details of papers named below (queries on: submodular subset selection, sensor placement in Gaussian processes, anchor points, soft-impute, probabilistic PCA, Ledoit-Wolf shrinkage, cold-start/active learning in recommenders, computerized adaptive testing, observational scaling laws, efficient benchmarking, LiveBench). Only titles and abstract snippets of search results were read; none matched the restricted paper's description to my knowledge, and nothing was opened or used from outside the starter list apart from those verified references.

## Timings
Final run of `run_everything.sh` (40-core machine, shared, second stage oversubscribed to ~80 processes): ~1.1 h wall-clock in total
(MTEB-main random split 11 min with 15 procs, org split 11 min, OpenLLM 21-22 min (4,496 models, leave-one-benchmark-out targets), HELM-22/10 15-16 min, conditions 7 min,
synthetic E1-E6 <= 5 min each). Summed per-fold wall times 22.7 h (inflated by oversubscription). RAM < 4 GB per process.
Re-running all experiments reproduced the earlier results bit-for-bit (all tables identical to 0.0).
