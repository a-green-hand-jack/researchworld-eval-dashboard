## Reproduce the completed synthetic study

Run from this repository root with Python 3.11 and the package versions in `provenance/environment-initial.txt` (NumPy, SciPy and pandas are the only statistical dependencies):

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python3 tests/check_synthetic.py
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python3 scripts/run_synthetic.py --reps 20000 --out results/synthetic-main.jsonl
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python3 scripts/exact_null_reference.py
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python3 scripts/summarize_synthetic.py
```

The full simulation measured 89.9 process CPU seconds / 89.9 computational wall seconds on the provided CPU resource, excluding startup/imports. Seeds are recorded in every result row. The raw main summary lines and figure-ready CSV are committed. MCSEs describe repeated simulation, not uncertainty about any real LLM population. See the handoff for interpretation and the additional caveats for zero observed events.

## Pinned real-experiment inputs and setup

```bash
python3 scripts/fetch_inputs.py --model 1.5B
```

This fetches supplied MMLU-Pro revision `b189ec765aa7ed75c8acfea42df31fdae71f97be` and pinned Qwen2.5-1.5B-Instruct Q4_K_M GGUF. `provenance/downloads.json` records exact URLs, sizes and SHA-256 hashes. `--model 0.5B` fetches the alternative pilot model, and `--model none` fetches only data. Large publicly downloadable model/data files are excluded from git. The dataset's `answer` and `cot_content` are never included in model prompts.

The backend is llama-cpp-python 0.3.18 built locally; exact source SHA/compiler/flags are recorded in `provenance/build-source.json` and `scripts/build_inference.sh`. That script uses the ResearchWorld compiler paths and source tarball path: on another machine install a compatible C/C++ compiler and CMake, download the pinned source tarball, and adjust those paths. `provenance/failures.md` preserves unsuccessful setup attempts. Setup verification and validation-only speed pilots precede any main run. The frozen bank is in `provenance/prompt-bank.json` and rendering code in `scripts/prompt_bank.py`; `prepare_real.py` freezes an independent question partition, and `run_real.py` produces raw generated-response caches with content/configuration checks before resuming. The original Tier B generation produced one complete6144-answer shard. Its measured elapsed-time gate activated the prespecified Tier C before main performance inspection:4 candidates,256 search and512 disjoint audit questions (3072 analyzed responses). All6144 calls/raw outputs remain charged and supplied. No second shard is generated. Primary accuracy targets11776 remaining benchmark items; design-adjusted exact intervals account for the runtime B/C choice. The separate empirical-cache calibration has known finite-cache truth. See [measured findings and limitations](docs/real-handoff.md), [frozen scope history](docs/real-scope-freeze.md), [exact commands](docs/real-reproduction.md), and [run log](docs/run-log.md). Numerical analyses complete in seconds after setup; regeneration measured75.66 elapsed hours,7.63 resource-active hours and15.58 processCPU hours, with different clock boundaries and unresolved discrepancy.
