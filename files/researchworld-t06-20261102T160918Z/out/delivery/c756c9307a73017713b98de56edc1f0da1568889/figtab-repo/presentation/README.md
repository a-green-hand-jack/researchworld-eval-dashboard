# Reproducing the final figures and tables

Run `python3 presentation/render.py` from the delivery root (or any directory). The renderer uses only the immutable measured summary slices in `presentation/inputs/`; it downloads no data and performs no model fitting. It checks input SHA-256 hashes against `presentation/provenance.json`, count/fraction agreement, actual-versus-budget edit use, and paired-control consistency. Rendering takes about 10 seconds on the supplied CPU environment. Exact package versions are recorded in `presentation/render_manifest.json` (NumPy, pandas, Matplotlib, Python). No rendering randomness is used.

To recompute the underlying evidence from raw public data, follow the analysis-owner reproduction instructions; this renderer is the final step. The copied slices originate at the exact analysis commit and paths in `presentation/provenance.json`. They are small result tables, not redistributed raw data. Percentages use `100 * fraction`; percentage-point differences also use `100 * difference`.

All assets are generated by `presentation/render.py`. Each figure has an editable generator, a vector PDF for the paper, and a PNG preview for inspection. Source slices and caption macros map as follows:

For integration, load `booktabs` and `graphicx`, then `\input{presentation/captions.tex}`. Tables are `tabular` fragments without floats. Suggested main paper: the first three figures at full text width; primary or one-percent table if space permits. The other displays fit the appendix. Paper owns float placement/numbering and can shorten captions while preserving the endpoint, uncertainty and upper-bound qualifications. Rebuild the proof from the delivery root with `pdflatex -interaction=nonstopmode -halt-on-error -output-directory=/tmp presentation/inspection.tex` (then copy `/tmp/inspection.pdf` to `presentation/inspection.pdf`). Inspect `presentation/inspection.pdf` for standalone typeset proof of all assets; this proof is a presentation check, not the manuscript.

Figures are designed at 5.5 inches with 7--9 pt native text. Do not substantially reduce their width. A table proof uses 8 pt text and is bounded by 5.5 inches. `budgets.tex` has wrapping cells and should remain full width. The generator leaves table font size to the manuscript. Avoid wrapping the primary table into a narrow single column.

## Presentation decisions and checks

- A log percentage scale makes the large range in found attack fractions visible; counts remain explicit. Baseline bootstrap ranges use a separate logit axis, with all interval endpoints in frame.
- Separate LLM datasets and all NBA seasons prevent a sports example from standing in for its full panel.
- Exact binomial Monte Carlo bars belong only to stochastic strategies. Kendall shading is a distribution of perturbation outcomes. Both differ from the baseline data bootstrap and the matched paired question bootstrap.
- Fixed-pair reversals, global winner changes and whole-ranking disagreement are separately named. Reversing the original leading pair necessarily displaces the original winner; the original runner-up need not become the new winner. Conversely, a winner change need not reverse that pair. Connecting lines between integer budgets do not claim a continuously measured threshold.
- The renderer verifies that no primary strategy saturates. The exact integer/fraction mapping is delivered, including the 990-game 2012 and 1,229-game 2013 NBA seasons.
- Matched fixed-reference and reselected-pair statistics remain separate. The fixed-reference follow-up is disclosed as post-hoc; neither statistic is a certified minimum attack.
- No cross-design causal comparison, method-novelty claim or new analysis is introduced by the rendering.
