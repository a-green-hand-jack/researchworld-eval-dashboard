# Prospective real experiment and analysis (before main responses)

Status: historical pre-main proposal, superseded by `provenance/real-scope.json` and `docs/real-scope-freeze.md` after the representative pilot and settled cost tiers. The following preserves the planning history. This records methods before any main responses; it does not report main measurements.

## Freeze and actual fresh-question target

Preferred scope is one Qwen2.5-1.5B-Instruct Q4_K_M model and the already frozen 16-candidate instruction/format bank. Partition seed 20261104 uniformly permutes the pinned 12032 MMLU-Pro test questions: first 512 form the selection pool, next 1536 form the disjoint audit pool. The remaining questions are not generated or inspected for outcome-driven choices. Candidate prefix order is baseline 0 followed by an outcome-independent permutation of ids 1–15, seed 20261105. Target weights are question/micro weights, matching uniform benchmark sampling, not equal subject weights. Validation-only pilots cannot change the bank to improve observed scores; their role is cost/format feasibility.

Search has n in {16,32,64,128,256,512} distinct selection questions and K in {1,2,4,8,16} candidates. For each of 20000 conditional selection repetitions, sample n questions without replacement from the frozen 512-question selection pool, choose the maximum accuracy among the bank prefix with independent uniform ties, and retain the reported score, winner identity and audit score. All bank/audit outputs are generated once and cached. These repetitions are selection resampling conditional on one generated response matrix, not independent model inference runs. At n=512 only ties/random-bank sensitivity can vary the full-pool winner.

The real fresh-question estimand is accuracy on questions outside the entire 512-question selection pool in this pinned finite benchmark (N=11520), for the frozen selected configuration. The 1536-item audit is a simple random sample without replacement from those N questions. Its score is an estimate, not known population truth. Conditional on the selection pool and selected candidate, exact equal-tailed hypergeometric inversion gives a finite-population confidence interval. Precomputing other frozen candidates for research does not change the prespecified selector: no audit score or main outcome can modify the bank, parser, primary grid or selected identity. We will not extrapolate this benchmark target to all future natural-language questions or other models.

For audit precision planning only (not a measurement), the worst-case fixed-candidate standard error with finite-population correction is approximately sqrt((11520-1536)/(11520-1))/(2 sqrt(1536)) = .01188, or 1.19 percentage points. A normal 95% half-width is about 2.33 pp; exact intervals depend on measured counts. Candidate-level simultaneous audit intervals use alpha/16 to protect all inspected frozen-bank means. Repeated selection trials cannot reduce audit uncertainty to Monte Carlo precision.

## Reliability and consequence evaluations

1. **Disjoint fresh audit:** report the mean reused-minus-audit gap and selected candidate identity/frequency, paired audit contrasts against frozen default 0, and descriptive sign/claim disagreement. No audit disagreement is labeled a known population false decision. Candidate-level exact audit intervals and paired-row bootstrap uncertainty accompany contrasts.
2. **Cache-based calibration:** separately treat all generated question rows as a finite empirical population with exactly known per-candidate means. Draw iid rows with replacement to rerun the whole search/report protocol and independent cached audit draws. Evaluate naive CP, simultaneous CP and independent/split reporting coverage, width, MSE, bias and the prespecified superiority rule against this conditional empirical truth. This tests performance under measured real prompt dependence but its fresh draws can repeat question identities; it is not the genuinely disjoint-question experiment and does not establish population coverage.
3. **Budget comparisons:** the main disjoint-audit comparison includes a half-search/half-holdout split from n selection-pool questions, evaluated against the same fresh audit for its own winner. Full budget comparisons (equal questions, equal calls and extra independent audit) are evaluated in synthetic and cache-based calibration experiments where their targets are exact. Report logical protocol calls separately from the actual total calls used to fill the complete response cache.
4. **Uncertainty:** every conditional Monte Carlo mean/rate gets MCSE; paired whole-question rows preserve covariance. A paired row bootstrap of selection and audit pools, with selection rerun, measures sensitivity to sampled questions and does not substitute for between-model/generation variation. Size the bootstrap from a timed analysis pilot. Show category counts, mean correctness/invalid rates and candidate covariance as diagnostics; avoid underpowered causal claims about subjects. Secondary random-bank ordering/subsets are explicitly sensitivity checks.

## Runtime and stopping rules, independent of outcomes

The representative validation pilot measures the main n_ctx=8192, 2-thread settings, all instruction/format families, category-first and longest validation inputs. Choose the 1.5B model if the target 16*(512+1536)=32768 responses fits a conservative 1.5x runtime forecast plus a reserved day for analysis/integration within the remaining week, and measured RSS has headroom below 4 GB. If it fails this cost/memory gate, reduce to 512 search +1024 audit at the same bank, or time the already downloaded 0.5B model before freezing a replacement; no outcome comparison chooses the model. Record the chosen scope and partition before any main answer. Do not silently lower K after seeing effects.

Use sequential question shards (two shards at preferred scope) so each tracked job fits the 259200-second job limit; the host is CPU-oversubscribed at this stage, so do not launch multiple large inference jobs concurrently. Check measured cost at flushed checkpoints. If a throughput-only forecast exceeds the predeclared time reserve, preserve completed rows and decide a predeclared question-prefix reduction without inspecting accuracy; record the shortfall and changed precision. Never select a promising subset by scores or fill missing outcomes artificially. Runtime, resource failures and max-token/format/range diagnostics are retained even if results are null.

## Score definition and provenance

Use deterministic greedy generated text, maximum 8 output tokens, the fixed Qwen chat framing and a strict capital-letter parser; malformed or question-option-out-of-range outputs are incorrect and diagnosed separately. A length ending is separately recorded and is not automatically called incorrect if the complete strict answer is valid. Model-input construction uses only question/options, never answer/rationale/source labels. The candidate function includes renderer, parser and decoding. Record exact model/data/script/prompt hashes, seeds, raw outputs, question/candidate ids, session records, cumulative token/time cost and resource accounting. A cache or configuration mismatch aborts rather than resuming silently.
