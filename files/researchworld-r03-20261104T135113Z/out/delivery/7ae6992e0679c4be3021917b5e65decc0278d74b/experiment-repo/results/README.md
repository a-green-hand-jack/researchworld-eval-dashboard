# Analysis code, data pipeline and results (delivered as `code/`, `data/`, `results/`)

Study: given a historical model x benchmark score matrix (missing cells allowed) and a new model that can run only k benchmarks, which k to
run, how to infer its scores on the others, and how large k must be.  Everything below is computed by the code in `code/`; nothing in
`results/summary|theory` is typed by hand.  Raw per-model result tables (`results/raw/*.parquet`, hundreds of MB) are not in git; they are
attached as a release asset of this repository (see "Raw results") and regenerated by `code/launch_sweeps.sh`.

## Protocol (as run)
* New-model setting: models are split into folds (`kfold` random 10-fold, repeated `reps` times; `lomo` leave-one-model-out; `group` leave-family-out, family = organisation for MTEB, `Base Model` for OLB,
  unlabelled models are singletons; `temporal` train on the earliest 4/5 of dated models, test on the latest 1/5, one fold).
* Everything that is fitted uses TRAIN models only: standardisation (train mean / sd per benchmark), factor-analysis fit, rank r (hold-out MSE on 10% of observed train cells, r in {1,2,3,4,6,8,12,16,24}),
  ridge strength (GCV), kernel width, and the selection ordering.  A held-out model reveals the first k benchmarks of the ordering that it actually has scores for; models with fewer than k scores are skipped for that k.
* **Protocol B (primary):** per repetition a random 25% of benchmarks (34% for N<=7) are fixed targets that are never selected; the error is measured on the held-out models' observed target cells only, so every k is scored on the same targets.
  **Protocol A (robustness):** targets are all remaining observed cells (target set shrinks with k).
* Metrics: `nmse` = pooled sum of ((prediction - truth)/sd_train_j)^2 over target cells / number of target cells (z-scale; the column-mean predictor, k = 0, scores about 1); `rmse_pts`, `mae_pts` in score points (MTEB / HELM / LiveBench scores x100; OLB already 0-100); `spearman` = mean over benchmarks of the Spearman correlation between predicted and measured scores across held-out models (only for a subset of selectors / methods / k).
* Uncertainty: per held-out model the sums are averaged over repetitions/folds/random draws; 95% percentile cluster bootstrap over held-out models (500 resamples; paired when comparing selectors).  Random selector: 10 independent draws per fold (5 for OLB sweeps).  Seeds: `--seed 0`, repetition i uses `default_rng(1000*seed+i)`, factor-analysis init seed = i.
* Selectors (`selector` column): `random`, `popular` (most-covered first), `rawvar`, `central` (mean |corr|), `kcenter` (farthest point on 1-|corr|), `lev` (rank-r leverage), `qr` (pivoted QR on the rank-r SVD), `dopt` (greedy log-det), `gv_fa` (greedy total conditional variance under the factor covariance), `gv_emp` (the same under shrunk empirical covariance), `gvc_fa` and `cheap` (cost-aware, only in `C_*`), `oracle` (see below).
* Inference rules (`method`): `mean` (k=0 baseline), `avgreg` (single average score -> per-benchmark linear map), `fa` (Gaussian factor-model posterior mean), `ridge` (GCV ridge on the completed train matrix), `knn` (10 nearest train models on the revealed benchmarks), `krr` (ridge + RBF kernel ridge on residuals), `pcals` (unregularised PCA projection; unstable, kept as a naive baseline in `A_*` of the small sets).
* **Floor** `F_*` runs: the same folds/targets, every observed non-target benchmark revealed (k label 999) = full-information predictor.  **Oracle** `O_*`: per held-out model, greedy forward selection of benchmarks that minimises that model's own target error under the `fa` predictor (it uses the target scores: an upper bound on what selection can give, not a method; optimistic by selection on the evaluation targets).
* **Pre-fixed k criterion** (PLAN.md section 3.5): G(k) = (E_mean - E_k)/(E_mean - E_floor), E_mean = column mean, E_floor = full-information error of the SAME inference rule (`G_own`, primary) or of the best rule (`G_best`); k*(g) = smallest k whose 95% bootstrap lower bound of G is >= g, g in {0.8, 0.9}; also absolute tolerances nMSE <= 0.5 / 0.25 / 0.15 and RMSE <= 3 / 2 points (upper CI bound <= threshold).  G can exceed 1 (finite-sample noise of a floor estimate); `avgreg` has a poor floor (single aggregate), so read its `G_own` with care.
* Measurement noise (C8): `noise_floor.py` uses `scores_per_experiment` (repeat runs inside one MTEB result file); only tasks with >= 2 experiments have an estimate (about 18% of dense56 cells, 28% of dense cells).  `datasets.csv: noise_nmse_z_covered` = mean noise variance of the cell value / sd_task^2 on those cells, a LOWER bound on the unavoidable error; no other seed information is in the files.

## Runs (`results/raw/<run>.parquet`; command in `code/launch_sweeps.sh`, parameters in `<run>.json`)
* `B_*` primary (protocol B, all selectors x all rules): `B_mteb_dense56` (3 reps), `B_mteb_dense`, `B_mteb_mid`, `B_mteb_sparse` (2 reps), `B_helm_mmlu` (5 reps), `B_olb`, `B_helm`, `B_livebench` (8 target draws, small N), `B_helm_lite_ext` (91 models x 28 HELM-Lite benchmarks built by `build_helm_ext.py`; 5 reps), `B_syn_*` (3 reps).
* `A_*` protocol A on every real set (and `A_olb`, `A_helm`, `A_livebench` with the earlier method list; `A_*` OLB/HELM/LiveBench have no `krr`).
* `F_*` floors matching each `B_*` and shift run; `O_*` oracle selection.
* Ablations on `mteb_dense56` (random 10-fold, same B protocol): `d56_mtrain{15,30,60}` (number of training models), `d56_miss{0.3,0.6,0.8}` (extra MCAR missing training cells), `d56_rank{2,4,8}` (fixed rank), `d56_logit` (logit transform), `d56_leak` and `hm_leak` (selection model fitted on the held-out rows too), `d56_lomo` (leave-one-model-out); `d56_selrank`, `d56_selrank2` (leverage / QR at fixed rank); shift: `d56_group`, `d56_famgroup` (strict family leave-out), `d56_temporal`, `d275_group`, `d275_famgroup`, `d275_temporal`, `olb_group`, `olb_temporal`; OLB `olb_mtrain*`; cost-aware budgets `C_d56`, `C_d275` (k = per-mille of the total evaluation time of the candidate benchmarks; cost from `data/mteb_task_cost_seconds.csv`).
* `X_*` (`results/raw/X_sel_B_<d>`, `X_rules_<run>`; written by `xrun.py`): extra selectors / rules on the folds, targets and ranks of the named run (same seeds), see `launch_review.sh`.
* Compute (wall-clock on a heavily shared host, so only an upper-bound indication; CPU-hours were not metered): `dense56` sweeps (3 reps, 6 rules x 10 selectors) 20-55 min each; `B_mteb_dense`, `B_mteb_mid`, `B_mteb_sparse` 1.5-3 h each; small-N sets minutes; OLB `krr`/`knn` runs 3-10 min per repetition.

## Status and caveats (updated with each push)
Final runs: every `B_*`, `A_*`, `F_*`, `O_*`, shift, ablation, cost and `X_*` run named above; summaries are regenerated from `results/raw` by the commands in `launch_*.sh` and `analyze.py` / `cluster_analysis.py` / `x_table.py` / `ood_detector.py` / `extra_summary.py` / `kstar_table.py` / `summarize_conditions.py` / `describe_data.py`.  Raw tables (about 0.4 GB) are a release asset of this repository (tag and URL are given in the issue thread world/experiment-repo#5 and #10).
Cluster-bootstrap CIs use 1000 resamples (the model-level CIs in `curves_*`, `paired_*` use 500).

Known limitations.
* Random k-fold splits are optimistic about a new model whose organisation / family is already in the matrix (73-80% of held-out models have >= 2 same-organisation or same-family models in the training set; `group_counts.csv`); `d56_group` removes the organisation only (47% still have family members); `d56_famgroup` removes the family.  The ranking of selectors is NOT stable across these splits (k* at G_own >= 0.8, `kstar_gap_*`; dense56, rule fa / krr): random folds gv_fa 4 / 2, dopt 3 / 3, random 8 / 5; organisation leave-out gv_fa 16 / 8, dopt 4 / 3, random 8 / 6 (gv_fa's advantage over random has paired CI covering 0 for k >= 3); strict-family leave-out gv_fa 5 / 2, dopt 6 / 8, random 8 / 6.  D-optimal is the most consistent informed selector under shift; the gv_fa advantage is robust only at k <= 2-3 (`paired_d56_group.csv`, `paired_d56_famgroup.csv`, `cluster_paired_B_*`).
* Temporal splits are one fold (rolling-origin version in `extra_*`) with 27-31 test models; the dense56 temporal drift is much larger than the dense (275) one, so the detector verdict (`ood_*`) rests on one strongly shifted case.  Trend terms (`trend_fa`, `trend_ols`, `trend` in `extra_*`) do not beat the plain factor posterior mean.
* Protocol B targets are a random 25% of the benchmarks (not a task-type block); OLB / HELM / LiveBench have 6-10 benchmarks, so 6-8 distinct target draws only (`target_draws.csv`); the oracle is optimistic; G uses an estimated floor.
* A larger-N LLM matrix could only be built from the pinned public sources as HELM-Lite-ext (91 x 28) and HELM-MMLU (79 x 57; the organisation column for HELM is a name-derived proxy); the pinned LiveBench export has 7 tasks and the pinned OLB export 6 aggregates (no per-subtask scores are pinned).
* Theory curves: `vs_real_<d>` uses the covariance fitted on all models (in-sample); `vs_real_trainonly_<d>` is the honest comparison and gives a Bayes curve that is optimistic by about 20-30% (median) relative to the realised CV error of `fa` on the MTEB sets and about 40% on HELM-MMLU (gap from estimating the covariance on few models and from misspecification; the ordering of the selectors is the same).
* Sparse matrix (`mteb_sparse`, 479 x 472, 30% observed, objective's own setting): a held-out model reveals the first k benchmarks of the ordering that it actually has scores for, and models with fewer than k scores are skipped for that k, so large-k points rest on fewer models.  The `krr` / `ridge` floors are poor here (0.43 vs 0.18 for `fa`, column mean 1.06) because these rules complete the matrix by mean imputation, so `G_own` for them is lenient; use `G_best` (floor of the best rule, here `fa`) for the honest k*.
* MTEB models are embedding models, not generative LLMs.
