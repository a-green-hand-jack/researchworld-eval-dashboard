# Reproduction notes

Everything here was produced by the code in `code/` on CPU. All numbers in the paper come from `results/` (per-run JSON, tidy CSVs, summary JSONs, `results/verdicts.md`).

## Environment
Python 3.11.2, PyTorch 2.14.1+cpu, NumPy 2.4.6, SciPy 1.17.1, pandas 3.0.6 (`results/env.txt`). Every run uses 1 CPU thread, float32, no GPU. Runs are seeded (`seed` fixes the init and the train/val split) but PyTorch CPU kernels are not guaranteed bit-identical across machines/thread settings, so on this host every re-run we made reproduced the stored per-run times exactly (see Reproducibility checks); across machines or thread settings we expect agreement of the qualitative result and, at best, of the times to within the logging resolution, but have not tested it. Install: `pip install torch --index-url https://download.pytorch.org/whl/cpu numpy scipy pandas`.

## Data
Synthetic, generated in memory (`code/grok.py::make_data`): all p² pairs (a, b) with label (a∘b) mod p. Tasks: `add` (a+b; main), `sub`, `mul`, `x2y2` (a²+b²), `rand` (a fixed random labelling, used for the capacity calibration E0b). Primary p = 59; p = 97 in E4. Train/val split: random permutation seeded by `10000+seed`, train fraction f; the `=` token is index p. No downloads, no third-party data.

## Code map
- `code/grok.py` -- one training run (config -> JSON with config, summary, logged curves). `python3 code/grok.py --help`. Models: `tfm` (1-layer decoder-only transformer, 4 heads, d_mlp = 4d, no LayerNorm, learned positions, N(0, 1/d) embeddings, readout at the last token) and `mlp` (concatenated embeddings of a and b -> ReLU(4d)). Width = d. AdamW (lr 1e-3, betas 0.9/0.98, wd 1.0), full batch.
- `code/sweep.py GRID OUTDIR [--workers N] [--shard i/n]` -- resumable sweep over a grid in `code/grids/`, one JSON per run (`OUTDIR/<run_id>.json`, written atomically; existing files are skipped).
- `code/collect.py RUNDIR PREFIX` -- tidy `PREFIX_runs.csv` (one row per run; first-crossing and sustained-crossing times, censoring flags) and `PREFIX_curves.csv` (≈60 log-spaced points per run).
- `code/stats.py` -- Kaplan-Meier median, bootstrap CI, permutation Spearman, log-log slope, lognormal Tobit slope, `cell_summary` (also used by figtab-repo's generators).
- `code/analysis.py` -- width-trend analysis for one setting (`analysis.py e1 RUNS_CSV OUT_JSON [--max-seed N] [--where QUERY] [--label TXT]`); `code/analyze_e1.py` (first-crossing E1 summary, early version); `code/analyze_e2.py` (outcome classes, Wilson CIs, f_gen(w); run on the E2 runs plus the E1 runs of the same family: `python3 code/analyze_e2.py results/E2/tfm_cells.csv results/E2/tfm_runs.csv results/E1/tfm_runs.csv`); `code/e2_slopes.py` (width slope per f); `code/analyze_e3.py` (time-scale exponents, collapse, tuned vs untuned trend; `--wd3-only` adds the width-only wd = 3 trends to the summary json); `code/e5_lite.py` (weight-norm trajectories from the logged curves of existing runs: `python3 code/e5_lite.py results/E5lite/e1 results/E1/mlp:results/E1/mlp_runs.csv:mlp results/E1/tfm:results/E1/tfm_runs.csv:tfm`); `code/capacity_ratio.py` (params/(f·p²) table and ratio bins from E1+E2: `python3 -W ignore code/capacity_ratio.py results/capacity_ratio results/E1/mlp_runs.csv results/E1/tfm_runs.csv results/E2/mlp_runs.csv results/E2/tfm_runs.csv`).
- `code/SPEC.md` -- frozen analysis definitions and the deviations log D1–D5.
- `results/verdicts.md` -- verdict per prediction P1–P7 with the number and source file for each line.

### Clean CPU-time estimate per experiment
The wall times above are measured on a host shared with other jobs (≈2.5 containers per CPU) and over-state the cost by a factor 1–5. `code/timing.py` measures the single-thread CPU time per full-batch step in isolation (p = 59, f = 0.5; `results/timing.csv`), and `code/cpu_estimate.py` scales it by steps run and by the number of training examples (log-log interpolation between timed widths; the evaluation cost is inside the timed step). Result (`results/cpu_estimate.csv`, estimated dedicated CPU-hours, to within ≈ 1.5× because of the interpolation and the linear-in-f p² scaling): E0b 2.5, E1 5.7, E2 10.3, E2b 1.2, E3 8.0, E3b 0.5, E4 1.2, E6 0.6, E7 1.4, E8 5.6, E9 0.7, E10 0.8, E11 0.1, E13 2.2, E8b 15.6, E14 4.0; total 60.3 CPU-h (E12, the Fourier runs, 0.9 h contended). Per-step cost at (f=0.5): MLP d = 16 … 256: 2.1, 3.2, 7.5, 19.5, 63 ms; tfm d = 16 … 256: 13, 16, 25, 50, 145 ms; depth 2: MLP d = 16/128 2.7/45 ms, tfm d = 16/64 36/68 ms.

### Reproducibility checks
- Entry points (`code/reproduce.sh`): `quick` re-runs 10 E1 runs (MLP d = 16/32/64 and tfm d = 16/32, seeds 0–1, `code/grids/QUICK_subset.json`; 10 min on two contended cores) and compares sustained t_fit99 / t_gen99 with the stored tables. Expected output: ten lines `OK  <model> d=<d> seed=<s>: t_fit99 a -> a, t_gen99 b -> b` and the last line `10 runs matched, 0 differ (tolerance 0.0 steps)`; observed output in `results/quick_check_collected_runs.csv`. `tables [PAPER_ROOT]` regenerates every tidy table, summary and bootstrap from `results/` and, given the paper-repo root, calls figtab's generators (a few hours, the bootstraps dominate); `figures PAPER_ROOT` only the figures and LaTeX tables (minutes).
- Exact reproduction on one host: in every comparison where a configuration was run twice on this host the t_fit99, t_gen99 and t_gen95 were identical: the 10 `quick` runs, the 20 E6 init_scale = 1 runs vs E1, the 50 E9 fine-logging runs thinned to the E1 logging vs E1 (25 per family), and the 9 runs below. We have no run across machines or thread counts (the statement that PyTorch CPU kernels are not guaranteed identical across machines still holds).
- The runs that were computed twice are the 9 E3 transformer d = 64 configurations lr 1e-3 / wd 3 and lr 3e-3 / wd 1 and wd 3, seeds 0–2 (the E3 tail was also swept from the reverse side by a helper). The first computation was overwritten by the second (same `run_id`), so those two cannot be compared directly. A third computation (E11, `code/grids/E11_repro_check.json`, `results/E11/e11_runs.csv`) equals the stored one in all 9 runs (t_fit99, t_gen99 and t_gen95 identical; wall time was 0.5× the stored one, i.e. less contention). So no t_fit / t_gen in the tables depends on which of the computations was kept.

Typical reproduction of one headline cell (MLP, f=0.5, E1): `python3 code/sweep.py code/grids/E1_mlp.json results/E1/mlp --workers 2; python3 code/collect.py results/E1/mlp results/E1/mlp; python3 code/analysis.py e1 results/E1/mlp_runs.csv results/E1/summary_mlp.json`. Note: the extra E1 transformer seeds (8–15) write into the same directory as the pre-registered 8 seeds, so the pre-registered analysis uses `--max-seed 7` (`results/E1/summary_tfm_seeds0-7.json`) and the full 16-seed analysis is `results/E1/summary_tfm_all.json`.

## Figures and tables -> scripts
Generated by `figures/make_figures.py` and `tables/make_tables.py` (figtab-repo) from the `*_runs.csv` / `*_curves.csv` above and the statistics in `code/stats.py`; the figure/table-to-input map is `figures/README.md` in the delivery. ## Deviations from the frozen spec (details in `code/SPEC.md`)
D1 E1/E2-MLP launched before the spec check; D2 tail check, Tobit under >20% censoring, long-cap check, fresh seeds for E3(ii), more E2 seeds near the transition; D3 the 0.99 threshold can be missed by plateaus at ≈98.6%, so 0.95 is reported alongside it everywhere; D4 extra transformer seeds in E1; D5 extra transformer seeds in E2 near the transition. E5 mechanism tracking beyond the weight-norm analysis (no Fourier/progress measures), parametrisation (µP-like) sweeps, p = 113 and widths > 256 were not run; the init-scale sweep is E6 (MLP only; analysis: `python3 code/analysis.py e1 results/E6/e6_runs.csv results/E6/summary_init0.5.json --where "init_scale==0.5"` for each scale, and `code/e5_lite.py` on the per-scale run tables `results/E6/e6_runs_init*.csv`) (see the last section of `results/verdicts.md`).
