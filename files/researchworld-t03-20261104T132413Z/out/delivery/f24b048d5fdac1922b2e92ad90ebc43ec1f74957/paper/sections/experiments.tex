\section{Experiments}
\label{sec:exp}
\subsection{Setup}
\paragraph{Data and models.}
We use public tabular binary-classification data (Appendix~\ref{app:setup}, Table~\ref{tab:setup}): Statlog German Credit ($d=20$), the folktables \citep{ding2021retiring} ACS Income ($d=10$) and ACS Employment ($d=16$) tasks (California, 2018, 1-year person file, 30\,000-row subsample), Give Me Some Credit ($d=10$, 20\,000-row subsample, median imputation) and Pima Indians Diabetes ($d=8$). Each dataset has a fixed stratified 70/30 split (seed 0); preprocessing is fit on the training part. Per dataset we train an $\ell_2$ logistic regression, a random forest, histogram gradient-boosted trees and a small MLP ($64\times64$); test AUC is $0.71$--$0.90$ across cells (Table~\ref{tab:setup}). 50 random test instances are explained per cell.
\paragraph{Explainers and budgets.}
We use the \texttt{shap} 0.51.0 \texttt{KernelExplainer} (paired sampling, \texttt{l1\_reg=False} in the main grid; the library's default \texttt{l1\_reg} is examined separately on four cells) and the \texttt{PermutationExplainer}. Each run sets its own seed explicitly, since in this version \texttt{KernelExplainer}'s \texttt{seed} argument does not seed the sampler. The budget axis is the number of model rows evaluated by one call. Kernel SHAP is exact once the number of coalitions reaches $2^d-2$, and the library's default of $2d+2048$ coalitions is clipped to that, so for $d\le11$ (in our data, $d\le10$) the default budget is exact and has no run-to-run variance; we therefore study budgets \emph{below} the default on these datasets, as a stress test (the smallest budgets, 20 to 60 coalitions, about 2.5 to 3 per attribute, are far below what a user would normally choose), and the default itself on the datasets with $d>10$. Each (cell, explainer, budget, instance) has $R=30$ independent runs.
\paragraph{Compute.}
A call takes between a few milliseconds and well under a second at the budgets used (Table~\ref{tab:cost}). The study answers the budget question for cheap models only; we do not examine an expensive model or a background so large that a user can afford only a few hundred rows. The whole study took about 73 CPU-hours on the world's meter (per-step table in \texttt{REPRODUCE.md}).

\subsection{Run-to-run error shrinks at the Monte-Carlo rate, but top-$k$ sets need much more}
Figure~\ref{fig:c1} shows the median relative $\ell_2$ error and the probability that a single run's top-3 set equals the reference's, against the rows evaluated. Across the \numnCells{} cells, the log--log slope of the mean error against budget is \numslopePermLo{} to \numslopePermHi{} for permutation SHAP (the Monte-Carlo rate $-\tfrac12$) and \numslopeKernelLo{} to \numslopeKernelHi{} for Kernel SHAP, which is steeper because its sampling is stratified and approaches enumeration; slopes are fitted only on budgets below half of the coalition space. Kernel SHAP at the smallest budgets occasionally returns a numerically singular solution (large errors), so we also report medians (Appendix~\ref{app:setup}).
Throughout, ``budget'' is the nominal number of coalitions (Kernel) or \texttt{max\_evals} (permutation), and the two do not cost the same: a permutation call of nominal $B$ evaluates a different number of rows than the $50B+1$ of Kernel SHAP, so the two explainers should be compared at equal rows (Figure~\ref{fig:c1} is drawn against rows; the table of Appendix~\ref{app:setup} lists both). Error is not what a user sees, however: at the smallest budgets the top-3 set of one run equals the exact top-3 set on average in only \nummatchSmallKLo{}--\nummatchSmallKHi{} of runs (Kernel) and \nummatchSmallPLo{}--\nummatchSmallPHi{} (permutation) depending on the cell, and in \nummatchLargeKLo{}--\nummatchLargeKHi{} and \nummatchLargePLo{}--\nummatchLargePHi{} at the largest budgets (Appendix Table~\ref{tab:c2}). Top-1 is much easier (\nummatchOneSmallKLo{}--\nummatchOneSmallKHi{} for Kernel at the smallest budget) than top-5 (\nummatchFiveSmallKLo{}--\nummatchFiveSmallKHi{}).
\paragraph{The library default where it is sampled.}
On the \numnDefaultCells{} cells with $d>10$ (German Credit with four models; ACS Employment with four models) the default budget of $2d+2048$ coalitions (\numdfltBudget) is itself an estimate, not an enumeration. A single default-budget run reproduces the exact-reference top-1 attribute in \numdfltMatchOneLo{}--\numdfltMatchOneHi{} of runs, the top-3 set in \numdfltMatchThreeLo{}--\numdfltMatchThreeHi{} and the top-5 set in \numdfltMatchFiveLo{}--\numdfltMatchFiveHi{}; two default-budget runs give the same top-3 set in \numpairDefaultLo{}--\numpairDefaultHi{} of pairs and the chance-corrected stability of the top-3 sets \citep{nogueira2018stability} is \numdfltNogueiraLo{}--\numdfltNogueiraHi{}. Signs are not the limiting factor: a run flips the sign of \numsignflipSmallKLo{}--\numsignflipSmallKHi{} of the reference's top-3 attributes at the smallest budgets and \numdfltSignFlipHi{} at the default (Table~\ref{tab:dflt}).

\subsection{Whether one run suffices depends on budget, model and the instance's margin}
Population-level adequacy is far from uniform. The fraction of instances whose top-3 match probability is at least $0.9$ ranges from \numadeqSmallKLo{} to \numadeqSmallKHi{} (Kernel) at the smallest budgets and from \numadeqLargeKLo{} to \numadeqLargeKHi{} at the largest, with the MLP and tree ensembles lagging the logistic regression in the same dataset (Appendix Table~\ref{tab:c2}). The instance's own margin explains much of this (Figure~\ref{fig:c2}): top-3 sets are far more reproducible for instances in the top tercile of the reference margin than in the bottom one, and the match probability is a nearly monotone function of the ratio $z$ of the reference gap to the run-to-run standard deviation of that gap (pooled, Figure~\ref{fig:c2}b; per cell with a normal-approximation reference curve, Appendix Figure~\ref{fig:zcell}). Because the standard deviation in $z$ is estimated from the same runs whose match probability is plotted, this monotone relation is partly a consequence of the definitions and is not an independent test of a model; it shows that the margin relative to the run-to-run spread governs the match, for both estimators. A deployer can compute the single-run margin directly (gap between the $k$th and $(k{+}1)$th absolute attribution, relative to the largest); $z$ needs repeated runs. At the default budget on the $d>10$ Kernel SHAP cells, flagging instances whose single-run margin is below 0.02 flags \numosDKLowFlag{}\% of the \numosDKLowN{} instances and leaves \numosDKLowFA{}\% (95\% CI up to \numosDKLowFAHi{}\%) of the unflagged ones with a top-3 match probability below 0.9, against \numosDKLowUnrel{}\% unreliable instances overall; at 0.05 it flags \numosDKMidFlag{}\%. The base rate is low there, so this is a weak test: on the sub-default budgets of the $d\le10$ cells (base rate \numosSKLowUnrel{}\% unreliable) the same 0.02 threshold leaves \numosSKLowFA{}\% of unflagged Kernel instances unreliable (\numosSKLowFALo{}--\numosSKLowFAHi{}\%), and \numosSPLowFA{}\% for permutation SHAP. The thresholds were not fixed in advance.
At the library-default budget on the $d>10$ cells (Table~\ref{tab:dflt}), the fraction of instances with top-3 match probability $\ge0.9$ is \numdfltAdeqLo{}--\numdfltAdeqHi{} across cells (Wilson 95\% bounds \numdfltAdeqLoCILo{}--\numdfltAdeqHiCIHi{}): a single default-budget run is adequate for most instances, but for a minority of instances the top-3 set of one run is not reliably the reference's. Since $R=30$ gives a Clopper--Pearson lower bound of only $0.905$ even when all 30 runs agree, we state this criterion at the population level (the fraction of instances), not as a per-instance guarantee.

\subsection{Comparison with other sources of variation}
Figure~\ref{fig:c3} puts every source of variation on the same scale: the probability that two top-3 sets that \emph{should} agree are identical. For two runs at the largest budget this is close to one. The background standard was run in full for $d\le10$ (ACS Income, Give Me Some Credit, Pima); for German Credit and the ACS Employment logistic regression only a reduced version exists (three redraws of 50 rows, \numbgRedInst{} instances, top-3 agreement \numbgRedLo{}--\numbgRedHi{}), so on the sampled-regime cells the comparison rests mainly on the retrain standard. Two models retrained on random 80\% subsamples of the training data (explained with the exact value function where $d\le16$, and by one Kernel SHAP run of 10\,000 coalitions for German Credit, where the estimator's variance is an estimated \numretrainNoiseSharePct{}\% at most of the disagreement) agree on \numstdretrainLo{}--\numstdretrainHi{} over cells, two background redraws of 50 rows on \numstdbgFiftyLo{}--\numstdbgFiftyHi{} and of 200 rows on \numstdbgTwoHundredLo{}--\numstdbgTwoHundredHi{}, whereas attributions of random other instances agree on \numstdnullInstLo{}--\numstdnullInstHi{} and random 3-subsets on \numstdnullSubLo{}--\numstdnullSubHi{} (chance). Thus, under this retraining protocol (80\% subsamples, five seeds, one data split) and these background draws, at the larger budgets explainer noise is smaller than the variation they induce; at the smallest budgets it is of the same order or larger. This is strongest in the sampled regime: on the $d>10$ cells the retrained models agree on the top-3 set in \numstdretrainSampledLo{}--\numstdretrainSampledHi{} of instances, below the \numpairDefaultLo{}--\numpairDefaultHi{} of two default-budget runs in \numnRetrainBelowRun{} of \numnRetrainCmp{} cells. The result depends on the subsample fraction: on the $d>10$ cells, agreement at 50\% subsamples is \numrsLoFifty{}--\numrsHiFifty{} (\numrsNFifty{} such cells) and at 95\% \numrsLoNinetyFive{}--\numrsHiNinetyFive{} (\numrsNNinetyFive{} cells: the four German Credit models and the ACS Employment logistic regression, forest and MLP), below two runs in all but the ACS Employment logistic regression (Appendix Table~\ref{tab:retrain}). On those datasets the variation that matters to a user is the one that comes with the model fit, not with the Kernel SHAP seed.

\subsection{Library defaults and the explained output}
Two choices a library user can make without noticing changed the result by more than the seed did in the cells where we tested them; these are remarks on a subset of cells (\texttt{l1\_reg} on four, the output on \numnLogitCells{}), not part of the reliability result. (i)~With the default \texttt{l1\_reg} (a LARS pre-selection of at most ten attributes), Kernel SHAP on German Credit (logistic regression, gradient boosting, MLP) does not converge to the Shapley values: at the default budget the median relative error is \numlOneDefaultErrLo{}--\numlOneDefaultErrHi{} against \numlOneFalseErrLo{}--\numlOneFalseErrHi{} with \texttt{l1\_reg=False} and does not shrink with the budget (\numlOneDefaultErrMaxLo{}--\numlOneDefaultErrMaxHi{} at 5000 coalitions); the top-3 set differs from that of the same-seed \texttt{l1\_reg=False} run in \numlOneChangedAtDefaultLo{}--\numlOneChangedAtDefaultHi{} of runs at the default budget (Appendix~\ref{app:l1}, Figure~\ref{fig:l1}), a bias of the sparsified target rather than noise. On the ACS Employment logistic regression the effect is small (median error \numlOneEmpDefaultErr{} against \numlOneEmpFalseErr{} at 5000 coalitions; top-3 differs in \numlOneEmpChanged{} of runs at the default). (ii)~Attributions of $P(y{=}1)$ and of the log-odds are different games: on the \numnLogitCells{} cells where we ran both, the exact top-3 sets coincide for only \numlogitSameThreeLo{}--\numlogitSameThreeHi{} of instances, while run-to-run reliability is similar or higher on log-odds (Table~\ref{tab:logit}; change in top-3 match probability, log-odds minus probability, averaged over budgets: \numlogitMatchDiffLo{} to \numlogitMatchDiffHi{} per cell and estimator). (iii)~We checked the German Credit reference against enumeration ($2^{20}$ coalitions) on \numrefN{} instances of \numrefNModels{} models (logistic regression and gradient boosting): the 20\,000-coalition reference is within $\numrefMaxRel\%$ of the exact vector in relative $\ell_2$ distance and has the exact top-3 and top-5 sets in \numrefTopThree{} of \numrefN{} checks (Table~\ref{tab:refcheck}).

\subsection{Repeating versus enlarging}
At matched compute, is the mean of $c$ runs at budget $b$ better than one run at $\approx cb$? The budgets of our grid are not generally a factor of $c$ apart, so we keep only pairs whose compute ratio lies within $[0.9,1.1]$ (for $c=4$, \numcfiveN{} of \numnCfourAll{} pairs; the remainder are not compute-matched and are not used). We pool the per-pair differences in top-3 match probability (repeat minus enlarge) with a bootstrap that resamples cells and then instances within cells; a second interval resamples the five datasets first. For Kernel SHAP the pooled difference is \numhmTwoK{} at $c=2$ (95\% CI \numhmTwoLoK{} to \numhmTwoHiK{}; datasets-first \numhmTwoDLoK{} to \numhmTwoDHiK{}; \numhmTwoPairsK{} pairs), \numhmFourK{} at $c=4$ (\numhmFourLoK{} to \numhmFourHiK{}; \numhmFourDLoK{} to \numhmFourDHiK{}; \numhmFourPairsK{} pairs) and \numhmEightK{} at $c=8$ (\numhmEightLoK{} to \numhmEightHiK{}; \numhmEightDLoK{} to \numhmEightDHiK{}; \numhmEightPairsK{} pairs): the single larger run is better, and the repeat wins in no cell at $c=2,8$ and in \numhmFourFavK{} of \numhmFourCellsK{} cells at $c=4$. For permutation SHAP there is no difference we can resolve: \numhmTwoP{} at $c=2$ (\numhmTwoLoP{} to \numhmTwoHiP{}; \numhmTwoPairsP{} pairs) and \numhmFourP{} at $c=4$ (\numhmFourLoP{} to \numhmFourHiP{}; \numhmFourPairsP{} pairs), and there are no matched pairs at $c=8$ (Figure~\ref{fig:c5}). The conclusion is limited to matched pairs, these two estimators and $c=2,4,8$.

\subsection{Predicting unreliable instances (exploratory)}\label{sec:diag}
We evaluated whether per-instance quantities available at deployment flag instances whose top-$k$ set is unreliable: the instance's own margin computed from a single run, and the signal-to-noise $z$ and match probability estimated from repeats. Median AUCs over cells and settings are \numaucMarginMed{} (own margin), \numaucRepeatZMed{} (repeat $z$) and \numaucRepeatPMed{} (repeat match probability) (Appendix, Figure~\ref{fig:c4}); this analysis was marked exploratory in advance and has not been compared with the variance estimate of \citet{covert2020improving}, so we make no claim that it improves on existing uncertainty estimates.
