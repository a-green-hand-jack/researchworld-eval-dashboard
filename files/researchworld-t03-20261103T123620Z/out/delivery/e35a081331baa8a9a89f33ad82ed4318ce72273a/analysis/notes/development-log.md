# Development issues, corrected before pilot

- Pandas 3 infers a dedicated string dtype, so German categorical detection by `dtype == object` failed. Categorical detection now uses `is_string_dtype`, and the expected raw feature units are checked before fitting. No German model or numerical result was produced with the incorrect detection.
- Pandas 3 rejects setting string categorical identities through `iloc` into an existing numeric column. ACS category conversion now assigns by column label. No ACS model or numerical result was produced before this correction.
- First SHAP import built a Matplotlib font cache. The timing pilot warms the library import outside timed calls; library startup is separate setup cost.
- Initial pilot completed all 9 model cells without failed estimator calls. It showed kernel budgets 512/2048 can be exhaustive for Diabetes, and 2048 exhaustive for ACS. Proposed stochastic budgets therefore change by feature dimension: Diabetes 32/64/128, ACS 64/256/512, German 128/512/2048. The exhaustive pilot calls remain deterministic controls, not evidence that stochastic methods always have zero variance.
- A permutation path estimator can visit every coalition but still has random path frequencies. `exhaustive` now remains false for that estimator and complete cache coverage is a separate flag. Old initial pilot `exhaustive` for permutation denotes cache coverage only; do not interpret it as exactness.
- Initial ACS loading reached peak cumulative process RSS 3,493,060 KiB, within but near the 4 GiB limit. Stream the ZIP member and parse only required columns in future acquisition rather than materializing the whole uncompressed person CSV. New-model loading must be checked after this change.
- Recorded the source CSV row indices for filtered ACS rows as well as positional split IDs, to make the main panel auditable against raw input. Main preprocessing/panel selection otherwise follows the same deterministic choices as the pilot.
- Numerical conditioning checks reject a rank-deficient constrained Kernel SHAP design. Main calls retain warnings and condition numbers. Exact references for every planned cell are now feasible by direct pilot timing; the independent approximate-reference proposal is superseded before main runs.
- A smoke run (two Diabetes logistic inputs, two repeats, three budgets/two estimators) produced and aggregated 24 calls in ignored development artifacts. It is an I/O/aggregation validation only, not included as main evidence.
- Tightened common-game numerical verification after observing up to 9.5e-9 agreement error between exhaustive library Kernel and direct enumeration on logistic models. Casting only the returned probability to float64 did not remove the discrepancy: a strict check failed at 2.98e-9 on ACS logistic pilot input0. Float32 prediction algebra can vary with batch shape. The predictor adapter now explicitly casts model inputs to float64 and accumulates probabilities in float64 for every estimator/reference. This changes numerical precision before any main run, not the feature values/game semantics. Final common-game checks and timing are recorded separately.
- The final float64 prediction adapter makes all 12 actual exhaustive Kernel/direct ACS/Diabetes pilot comparisons agree within 4.45e-16. Because this precision change can affect prediction speed, a tracked final-precision timing pilot repeats the actual reference/budget timings before main launch. It is not additional reliability evidence.
- Chunked ACS CSV parsing reduced the measured loader peak to 259,180 KiB (same195,665 filtered rows and10 feature units), from the initial3,493,060 KiB. This is a setup optimization, not data subsampling.
- Optional independent TreeExplainer random-forest probability control was tested against existing exact pilot values. It failed the1e-6 agreement/efficiency check on all five tested cases (maximum feature error roughly1.1e-4–3.7e-4; efficiency residual also nonzero). The first strict test raised an exception; the diagnostic runner now retains vectors/endpoints instead of discarding the negative result (`results/tree_control_validation.json`). It is NOT used as an oracle and supports no general statement about Tree SHAP; version/numerical compatibility remains unresolved. Full direct enumeration stays the reference for every main game. This does not affect the exhaustive Kernel/direct agreement check, which passes at4.5e-16.
