# Reproduce the GATE analysis

Run these commands from the paper delivery root (the directory containing
`code/`, `analysis/` and `results/`). Use Python3.11; exact measured package versions
are in `code/environment.json` and `code/requirements-lock.txt`.

```sh
python3 -m pip install -r code/requirements-lock.txt
python3 -m pip install --no-deps -e ./code
python3 code/scripts/download_data.py
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  python3 -m unittest discover -s code/tests -v
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  python3 -u code/scripts/run_study.py --workspace .
```

The launcher reads the original configs under code/configs, uses the hash-checked
public graph downloaded to code/data, and writes results/ at the delivery root.
All eight mechanisms and nine estimator outputs are generated; fresh-assignment
prediction outcomes are evaluated without supplying them to the estimator.
A recorded independent feasibility gate must be cleared in the manifest before
production launches. Corrected production completion is established only by final_execution.json and the complete boundary/checkpoint/summary audits; the v1 artifacts described in exposure_boundary_correction.md are superseded.

Execution is CPU-only, one BLAS/OpenMP/MKL thread, and checkpointed atomically by
cell. The same command resumes completed cells and computes unfinished ones.
The conservative calibrated production allowance is approximately7.30hours,
including a factor-two contingency, exact HT risk, summary projection and a selected-replay/audit reserve; actual measured corrected execution
is in analysis/final_execution.json and execution_reconciliation.md. The full design uses102cells/R400, with graph
seeds201–205 and masters2202601(core),2202602(noise),2202603(imbalance). Each
replicate's assignment, noise and prediction stream seeds are saved with it.

Existing results are not recomputed merely because the command is repeated.
For a clean reproduction, prepare a self-contained workspace before launching.
Preparation copies code/configs, the downloaded graph (if available), and reference
documentation. It copies **no results**. Original receipts are preserved under
`analysis/reference_delivery/`; fresh receipt paths initially do not exist.

```sh
python3 code/scripts/reproduce_workspace.py prepare --workspace /path/to/reproduction
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  python3 /path/to/reproduction/code/scripts/run_study.py --workspace /path/to/reproduction
python3 /path/to/reproduction/code/scripts/reproduce_workspace.py postprocess \
  --workspace /path/to/reproduction
```

If the public graph was not downloaded before preparation, first run
`python3 /path/to/reproduction/code/scripts/download_data.py`.
Preparation also supports an existing **results-only** workspace generated by the
old `run_study.py --workspace` command. It refuses existing `code/` or `analysis/`
paths, protecting previous receipts. Postprocessing runs once per preparation and
refuses to overwrite its own previous receipt. After a failed attempt preserve the
workspace and prepare another results-only copy to retry.

Postprocessing runs with the copied source/configs and explicit workspace root.
It regenerates summaries, support bounds, full checkpoint/ledger and integer-boundary
audits, diagnostics and independent contrasts, raw-to-summary/decomposition checks,
the historical graph-dependency comparison, a fresh selected four-cell replay,
findings/94-row claim registry and supplementary arithmetic audit. All are written
to the reproduction's `results/` and `analysis/`. Per-stage actual wall/CPU/RSS,
commands and fresh output hashes are in `analysis/workspace_postprocessing.json`.
Its `passed` status requires every stage. The simulator/core scientific modules and
frozen configurations are unchanged by this packaging workflow.

Original resource accounting and full-study execution receipts remain historical
reference files; they are not new-host timing evidence. `execution_manifest.json`
is a fresh copied-source hash snapshot, not the original resource job's status.
New per-cell timings remain in the new run's raw metadata. The findings generator is invoked from the copied workspace code, whose native
root is that workspace; its original source identity is preserved. The workspace
receipt supplies reproduction provenance alongside byte-identical findings and
claim values. The legacy postprocessing
commands below operate on the delivered root; they do not audit a separate clean
workspace. Use the prepared workflow above for that purpose.

Source snapshot, graph/config hashes, graph summaries and timing/RSS accompany
production cells. The downloader validates the frozen SNAP SHA256. Raw public
data are not redistributed; attribution/terms are in code/data/manifest.json.
No prohibited-paper access has occurred; only supplied materials and explicitly
permitted source data were accessed by the analysis position.

Numerical outputs are in results/production_{core,noise,imbalance}; raw replicates
are Parquet and exact one-hop HT risk is in each stage's exact_ht/ JSON. Numerical
summaries are results/summary/performance_by_graph.csv, performance_by_family.csv,
paired_by_graph.csv and paired_by_family.csv, produced by gatebench.summarize.
The launcher also computes results/support_bounds.json using
`gatebench.support_bounds`. A standalone summary command is:

```sh
OPENBLAS_NUM_THREADS=1 python3 -m gatebench.summarize \
  results/production_core results/production_noise results/production_imbalance \
  --output results/summary
```

Analysis and failure-denominator interpretation are in analysis/methods.md.
Historical pre-correction pilot outputs are supplied as timing/calibration evidence only (results/calibration_status.md); their numerical boundaries were not corrected and they are not accuracy authority. Their graph
identities and streams can overlap across calibration panels, so they must not
be pooled as independent graph-population performance evidence. The presentation
owner supplies the separate script-to-figure/table mapping and rendering commands.

The gate is now cleared by the independent feasibility decision preserved in
analysis/independent_feasibility.md. Final seed policy uses distinct masters, with
master included in pairing IDs. Floating endpoint truth is a diagnostic range,
not a family-group identity. Undefined RMSE confidence intervals retain missing
endpoints. Thirteen scientific checks exercise the implemented pipeline and scoring.

Supplementary diagnostics and verification (after all production stages finish):

```sh
OPENBLAS_NUM_THREADS=1 python3 code/scripts/audit_results.py --root . --complete
OPENBLAS_NUM_THREADS=1 python3 code/scripts/audit_boundaries.py --root .
OPENBLAS_NUM_THREADS=1 python3 code/scripts/analyze_results.py --root .
OPENBLAS_NUM_THREADS=1 python3 code/scripts/audit_summaries.py --root .
python3 code/scripts/replay_selected.py --source . --workspace /path/to/clean/replay
```

The selected clean replay reruns four predeclared structural-extreme cells with
allR400replicates, then compares every output column to production. The supplied
receipt records an actually completed115200-row exact replay; it is not a full
production rerun or an independent statistical implementation. Supplementary
output definitions and H1–H4 evidence routes are analysis/supplementary_analysis.md.

## Rational-boundary correction and safe resume

First-order exposures count treated neighbors before dividing by degree, avoiding step-boundary roundoff at .75/.85. See analysis/exposure_boundary_correction.md for the superseded v1 execution, exact repair and unchanged scientific configs/streams. The root launcher now refuses to resume an existing checkpoint whose source/config metadata differ, and advises preserving it and using a clean workspace. The corrected execution used three disjoint34-cell shards in a clean workspace; the ordinary full launch command reproduces the same scientific rows sequentially. The complete finalization additionally runs audit_boundaries.py, which replays all40800saved assignments using independent integer inequalities and performs no regression fitting.

After those audits and the selected replay, regenerate the analysis handoff and
verify its exact row routes:

```sh
python3 code/scripts/audit_v2_dependencies.py --root .
python3 code/scripts/final_report.py
OPENBLAS_NUM_THREADS=1 python3 code/scripts/audit_diagnostics.py --root .
```

`audit_v2_dependencies.py` uses the supplied archived graph metadata to establish
structural content applicability only. `reconcile_execution.py` describes the original
tracked resource execution and expects its saved resource receipts; it is not a
portable profiler for a new host. New simulation wall/CPU/RSS values are recorded
per cell in that run's metadata. `complete_corrected_study.py` is the historical
three-shard installer, which moves local prior outputs aside; ordinary reproduction
uses `run_study.py` and a clean workspace. New timings/receipts need not match the
original host even when scientific outputs match exactly.
