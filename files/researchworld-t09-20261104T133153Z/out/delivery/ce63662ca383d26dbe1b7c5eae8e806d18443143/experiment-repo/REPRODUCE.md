# Reproducing the study (experiment-repo part)

Everything in `results/` is produced by the scripts in `code/`; nothing is typed in by hand. Status of the numbers (which grids are complete, which cells were **not run**) is in `results/COMPLETENESS.csv` and `results/CELLS_NOT_RUN.csv`; do not read a partial grid as complete.

## 1. Environment
Python 3.11.2; numpy 2.4.6, scipy 1.17.1, pandas 3.0.6, scikit-learn 1.9.1, networkx 3.6.1, pyarrow 26.0.0 (compact data), pytest 9.2.0 and statsmodels 0.15.0 (unit tests only) (lock: `code/requirements.lock`). CPU only, no GPU. One process per CPU (`OMP_NUM_THREADS=1`).
```
pip install -r code/requirements.lock
```

## 2. Data (only graphs; no outcome data exist: outcomes are simulated from potential-outcome models)
| graph | file | sha256 |
|---|---|---|
| socfb-Stanford3 (11,586 nodes, 568,309 edges) | `https://nrvis.com/download/data/socfb/socfb-Stanford3.zip` → unzip `socfb-Stanford3.mtx` into `$NETGATE_DATA/stanford/` | zip `b1221e414dbaf3278468f60881bac932e935b8813020157bc6fb3823f5e8720d` (matches `data.md`) |
| SNAP ego-Facebook (4,039 nodes, 88,234 edges) | `https://snap.stanford.edu/data/facebook_combined.txt.gz` → `$NETGATE_DATA/ego/` | `125e84db872eeba443d270c70315c256b0af43a502fcfe51f50621166ad035d7` (matches `data.md`) |

`NETGATE_DATA` defaults to `/hutian/data`. The largest connected component is used (Stanford3 is connected as downloaded: 11,586 nodes). Synthetic graphs (SBM, Barabási–Albert, Watts–Strogatz, Erdős–Rényi) are generated by networkx inside `code/src/netgate/graphs.py`. Louvain partitions of the two real graphs are cached in `results/cache` (`NETGATE_CACHE` to move it); synthetic-graph partitions are never cached (a cache keyed only by the graph family name in the first launch gave wrong labels across worlds; that launch was discarded and everything was rerun).

## 3. Seeds
Each grid cell has a fixed integer `seed` in `code/src/netgate/experiments.py`; world `w` of a cell uses `numpy.random.default_rng(seed*1000+w)` for the graph (synthetic only), baseline/noise and the assignments (replicate `r` is seeded with `r`). Real graphs are fixed; only baselines and assignments vary. 4 worlds × 100 assignments per cell (400 estimates per cell and estimator) in e1–e5, e7, e10; e6 4 × 150; e8 2 × 60 and e9 2 × 50 (noiseless, so only the assignment and the graph vary; coverage is not read from them). Post-freeze grids: e13 2 × 50 / 4 × 100, e14 8 × 50, e15 4 × 150, e16 4 × 100 (same seeds as the Bernoulli cells of e2), e17 4 × 100, e18 20 × 25, e19–e21 4 × 100. The exact per-grid values are in `results/tables/t13_grid_spec.csv` (`code/scripts/grid_spec.py`).

## 4. Commands (from the repository root; `code/` is the code directory)
```
for e in e1 e2 e3 e4 e5 e6 e7 e8 e9 e10 e11 e12 e13 e14 e15 e16 e17 e18 e19 e20 e21; do python3 code/scripts/run_experiment.py $e --procs 2 [--shard i/k] [--reverse]; done   # writes results/raw/<exp>/<cell>.csv.gz, resumable
python3 code/scripts/aggregate.py          # results/summary/<exp>.csv  (bias, sd, rmse, rel_rmse, coverage, MC SEs); `--compact` reads results/compact/*.parquet instead of the raw files
python3 code/scripts/theory_bias.py        # results/summary/theory_vs_sim_e9.csv  (exact-binomial closed-form bias vs e9)
python3 code/scripts/make_tables.py        # results/tables/t1..t10  (claim-level tables)
python3 code/scripts/findings.py           # results/hypotheses.csv  (H1..H8 tests with decision rules and verdicts)
python3 code/scripts/factor_ranking.py     # results/tables/t11_factor_ranking.csv  (C3)
python3 code/scripts/completeness.py       # results/COMPLETENESS.csv, results/CELLS_NOT_RUN.csv
python3 code/scripts/runtime_table.py      # results/RUNTIME.csv
python3 code/scripts/post_freeze.py        # results/hypotheses_postfreeze.csv, tables/t14 (H3 gamma), t15 (Hajek), t16 (second seed); e11-e13 are post-freeze additions
python3 code/scripts/variance_law.py      # tables/t17, t17b, t17c  (variance law with d_h, e1/e3/e21)
python3 code/scripts/exposure_diagnostics.py  # tables/t18  (Var(f), within-arm Var(f), corr(z,f) under cluster designs)
python3 code/scripts/coverage_analysis.py  # tables/t19, t19b  (coverage of the GATE vs of E[tau-hat], by interval; e6, e15)
python3 code/scripts/world_uncertainty.py  # tables/t20, t20b, t20c  (variance components, worlds needed, headline intervals)
python3 code/scripts/crossover.py          # tables/t21, t21b  (gamma*, variance ratio vs n, d, sigma; e17)
python3 code/scripts/factor_anova.py       # tables/t22, t22b  (variance decomposition of log RMSE; e20)
python3 code/scripts/heavy_tail.py         # tables/t23  (matched heavy-tail test; e14)
python3 code/scripts/cluster_hajek.py      # tables/t24  (design-based baselines under cluster designs; e19)
python3 code/scripts/estimator_scope.py    # tables/t25, t25b  (OLS_zf, ridge, lasso, tuned GBM; e16)
python3 code/scripts/compact.py [--check exps]  # results/compact/<exp>.parquet, and the check that aggregate.py --compact reproduces the summaries
python3 -m pytest code/tests -q             # 16 unit tests, ~9 s (needs pytest, statsmodels)
python3 code/scripts/headline.py           # results/tables/t12_headline_numbers.csv  (headline numbers with MC SE and source rows)
python3 code/scripts/grid_spec.py          # results/tables/t13_grid_spec.csv, t13b_real_graphs.csv  (worlds x assignments, graph sizes)
python3 code/scripts/package_delivery.py <dest> --raw-tar raw_results.tar.gz   # assembles code/, results/, MANIFEST.md, REPRODUCE.md
```
`--shard i/k` runs cells with index ≡ i mod k, `--reverse` goes last-to-first (used to let two jobs meet in the middle). Cells are independent, so sharding does not change any number.

## 5. Expected runtime (measured; 2 CPUs per job on a heavily shared host, so wall time is roughly twice these CPU-hours)
Median seconds per cell / CPU-hours per grid, from the `secs` column of the raw files (cells that stalled on the shared host, ≥10⁴ s, excluded): see `results/RUNTIME.csv` (`runtime_table.py`). All 21 grids together are ≈ 67 CPU-hours (the first ten ≈ 58: 1.4 h for e9, ≈ 15 h for e2, ≈ 11 h for e7; e11–e21 ≈ 9 h, of which e16 2.5 h, e13 3.3 h).

## 7. Raw data and compact data
`results/compact/<exp>.parquet` (≈ 70 MB in all, in the paper repository) holds every replicate of every grid (columns of the raw files without the cell wall-clock; estimates and GATE float64, the rest float32). `python3 code/scripts/aggregate.py --compact` rebuilds `results/summary/*.csv` from them (relative difference to the shipped summaries ≤ 3.5·10⁻⁷, `compact.py --check`), so a reader can re-aggregate, recompute coverage or refit anything without the raw files. The per-replicate raw files (≈ 175 MB gzipped, needed only for `RUNTIME.csv` and the cache-free re-run check) are not part of the paper repository; they are attached to the release `raw-results` of the `experiment-repo` repository (tarball `raw_results.tar.gz`, sha256 in `results/MANIFEST.md`); the post-freeze grids e11–e12 are in the same release as `raw_results_e11_e12.tar.gz` (sha256 `846a8684ebf8d866a56aef6e6ac2b0d85c787a2861e74aa0f2d9880a4b63dcfc`), e13–e21 are in `raw_results_e13_e21.tar.gz` (sha256 in `results/MANIFEST.md`). `results/summary/*.csv` is exactly reproducible from them with `aggregate.py`.

## 9. Known limits and caveats of the data
- **Decision rules are not pre-registered.** Hypotheses and predicted directions come from the plan; the numeric thresholds of `findings.py` were written after the e1–e10 runs had finished and after the claim tables had been looked at. The thresholds of `post_freeze.py` (H3g, H6c/d) were written before the e11 cells and the e12 bias values were read, which the commit history cannot show (first committed after the results). Details: `results/FINDINGS.md`, preamble and "Post-freeze additions".
- Truth is model-defined (exact GATE of the simulated potential-outcome function), not observed; one outcome-model family per mechanism.
- Hájek estimators: HajekFull has n_rep < full count where no unit has full-neighbourhood exposure and HajekKappa is unavailable under cluster designs; they are reported as unestimable (with n_rep/n_nan in the summaries), the post-freeze grid e12 uses low-degree graphs where they are estimable (FINDINGS, H6c–e).
- e6, BA graph, analysis-cluster resolution 0.5: a single analysis cluster, so the cluster-robust SE is degenerate (≈1e-13, coverage 0); that cell's cluster-robust column must not be read.
- e8/e9 are noiseless (σ=0, no baseline heterogeneity): only bias is read from them.
- Not done: GNN and other learners and staggered rollout (cut per the plan's order); no grid cell was cut (1622/1622 complete: 806 in e1–e10); the two parts untested at the first freeze (H3 γ-dependence, Hájek baselines) were run afterwards as e11/e12 and the later requests of `paper-repo` as e13–e21 (post-freeze, see FINDINGS); unit tests exist (`code/tests`, 16 pass) and check HC0, cluster-robust (statsmodels) and one-hop HAC (by hand); two-hop HAC and the Hájek variances have no independent check. See `results/FINDINGS.md` ("What was not done", "Checks that were actually run").
